# Checklist antes de entregar

## Contenido que debes personalizar

- [ ] Reemplazar los integrantes en `README.md`.
- [ ] Agregar la URL pública del repositorio.
- [ ] Agregar la URL de GitHub Pages después del despliegue.
- [ ] Confirmar que cada integrante entiende el HTML, CSS y JavaScript completo.

## Git obligatorio

- [ ] `main` tiene protección y exige Pull Request.
- [ ] Nadie hizo commits directos a `main`.
- [ ] Cada integrante tiene al menos 1 PR mergeada.
- [ ] Cada PR tiene aprobación y un comentario de review sustantivo.
- [ ] Cada integrante tiene al menos 3 commits propios.
- [ ] Los commits siguen Conventional Commits.

## Rúbrica técnica

- [x] Cuatro páginas: Home, Catálogo, Detalle y Contacto.
- [x] HTML semántico con `header`, `nav`, `main`, `section`, `article` y `footer`.
- [x] Todas las imágenes tienen `alt` descriptivo.
- [x] Todos los campos del formulario tienen `label` asociado.
- [x] Bootstrap 5 cargado desde CDN.
- [x] `css/custom.css` cargado después de Bootstrap.
- [x] CSS mobile first, variables propias y más de 30 líneas.
- [x] Grid con `col-sm-*` y `col-lg-*`.
- [x] Más de 3 componentes Bootstrap personalizados.
- [x] Más de 2 eventos propios con `addEventListener` que modifican el DOM.
- [x] Portadas optimizadas en WebP.
- [ ] Ejecutar W3C Validator con cada HTML.
- [ ] Probar en 390 px y 1440 px sin desbordes.
- [ ] Confirmar consola sin errores.

## Presentación de 5-7 minutos

- [ ] 45 s: problema, concepto y público del catálogo.
- [ ] 90 s: demo Home, Catálogo, Detalle y Contacto.
- [ ] 60 s: Bootstrap, responsive y CSS custom.
- [ ] 60 s: eventos JavaScript propios.
- [ ] 60 s: ramas, PRs y Code Review de cada integrante.
- [ ] 30 s: cómo evolucionará a API en la Evaluación 2.

## Punto importante

La calidad visual por sí sola no compensa incumplir el flujo Git. La pauta reprueba automáticamente si falta un PR mergeado por integrante, Code Review o commits propios.
